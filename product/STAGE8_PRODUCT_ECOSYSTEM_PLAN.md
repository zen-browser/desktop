# Stage 8 - Product Ecosystem Plan

## Goal

Prepare the non-browser infrastructure needed for a real Nevai Browser product.

This stage can be planned early, but implementation should wait until the desktop alpha path is clear.

## Repositories

Optional future repos:

- `nevai-website`
- `nevai-docs`
- `nevai-updates`
- `nevai-services`

Do not create empty repos unless there is immediate work to put in them.

## Website

Required before public alpha:

- download page
- release notes
- known issues
- source link
- privacy policy
- support link
- security reporting link

## Docs

Required before public alpha:

- install instructions
- update policy
- known limitations
- issue reporting guide
- license/source attribution

## Updates

Do not start production update infrastructure until:

- Stage 2 artifacts exist
- package identity is stable
- signing strategy is known
- staging update flow is designed

## Support

Required before public alpha:

- GitHub issue templates
- triage labels
- security advisory path
- known issues process

## Privacy And Compliance

Required before public alpha:

- privacy policy
- external services inventory
- telemetry/crash-reporting decision
- license attribution review

## Done Criteria

Stage 8 planning is complete when:

- website requirements are documented
- docs requirements are documented
- update infrastructure is not faked
- support workflow is documented
- privacy/legal blockers are visible
